The Ship Kit v1.0.13

Security audit tip sheet

The security audit looks for ship-blocking problems a non-developer can understand and fix. Run it first, fix Critical items first, then move on.

This kit is a checklist and audit aid. It is not a security guarantee, penetration test, or legal advice. You are responsible for your app, your keys, and your launch.

How to run it

Install the kit first with the setup guide, then restart your tool.

Claude Code

In chat, say: Use the security-audit agent on this project

Or type: /security-audit

Cursor

In Agent chat, ask: Run a security audit using the Ship Kit security rule or @ship-kit-security

Claude Code: supported, but not yet tested live on Claude Code. The Cursor version has been tested live. If something behaves differently in Claude Code, tell us and we will fix it.

What "Critical" means

Critical means do not launch until it is fixed. Someone could read other people's data, get paid access for free, or change what they pay. Fix every Critical item first, then High, then the rest.

Some things are always Critical, for example:

  • A Supabase table in the public schema that holds user data and has RLS (row level security) off.
  • A policy that lets anyone read rows that belong to one user, like private messages or contact details.
  • A server that charges from a price, amount, currency, quantity total, or Price ID sent by the browser.
  • A column a user can change on their own row that gives admin or paid access, like role, plan or is_pro.

What it looks for

  • Secrets and keys: Stripe secret keys, Supabase service role keys and other tokens in your code or in a committed .env file.
  • Auth: pages and API routes that should check who is logged in but do not.
  • Ownership: routes that take a user or record id without checking it belongs to the person asking.
  • Supabase RLS: tables with RLS off, and policies that let anyone read or write.
  • Stripe: webhook handlers that skip the signature check (constructEvent), secret keys in client code, and prices taken from the browser.
  • Injection, headers and cookies: raw SQL built from user input, session cookies without secure settings, and open CORS.

What you get back

A short report: a summary (ready to ship or not), then Critical, High, and Medium or Low findings with plain fix steps, what looked fine, and the limits of the check. It reads your files first and asks before risky edits. It shows only the first 4 characters of any secret it finds.

It cannot check what only runs live, like your Stripe dashboard or your production database with real users. Check those yourself with the launch checklist.

After the audit

  1. Fix Critical items, then run the audit again.
  2. Walk the launch checklist.
  3. Run /pre-launch (Claude Code) or @ship-kit-prelaunch (Cursor).
